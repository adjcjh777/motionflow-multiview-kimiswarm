# P18: WebBridge Cross-Dataset Benchmark Plan

**Branch:** `feat/swarm-iter18-omniview`  
**Status:** Planning / ready for smoke  
**Related:** `docs/swarm_iter18/P11_paper_story.md`, `docs/swarm_iter18/P02_omniview_arch.md`, `docs/swarm_iter_next/iter_webbridge_data_integration_plan.md`

---

## 1. Why now

The best single-dataset result is **8.35 mm MPJPE** on MPI-INF-3DHP S2/Seq1 (Bayesian tri v2 ensemble). For ICRA/CVPR 2027 we need to show that the same architecture generalises across capture rigs, skeleton conventions, and scene layouts. This plan defines a reproducible cross-dataset benchmark over MPI-INF-3DHP, Human3.6M, AIST++, Shelf, and Campus using the existing WebBridge canonical `.npz` pipeline.

---

## 2. Datasets & canonical assets

All datasets are available in `data/webbridge/` in the canonical layout:

```
points_2d   (T, V, J, 2)
confidences (T, V, J)
joints_3d   (T, J, 3)
camera_K    (V, 3, 3)
camera_R    (V, 3, 3)
camera_t    (V, 3)
```

| Dataset | Views | Joints | Train split (representative) | Test split | Canonical path pattern |
|---|---|---|---|---|---|
| MPI-INF-3DHP | 14 | 28 → 17 | S1/S3/S4 `s_*_seq_*_v14_multiview_m.npz` | S2/Seq1 | `data/webbridge/mpi_inf_3dhp/...` |
| Human3.6M | 4 | 17 | S1 actions 2–16 | S9/S11 actions 2–16 | `data/webbridge/h36m_meters/s_*_acts_*_multiview_m.npz` |
| AIST++ | 9 | 17 | style-based split (see §4) | 2–3 held-out genres | `data/webbridge/aistpp_canonical/...` |
| Shelf | 5 | 17 | `shelf_seq1_train_v5_multiview_m.npz` | `shelf_seq1_val_v5_multiview_m.npz` | `data/webbridge/shelf_campus/...` |
| Campus | 3 | 17 | `campus_seq1_train_v3_multiview_m.npz` | `data/webbridge/shelf_campus/...` |

### 2.1 Skeleton unification

* MPI-INF-3DHP is stored with 28 joints; for cross-dataset work it is remapped to the common 17-joint H36M skeleton using `motionflow_mv.data.webbridge_mixed_dataset.SKELETON_MAPS["mpi"]`.
* H36M, AIST++, Shelf, and Campus already use the 17-joint layout.
* The mixed loader `motionflow_mv.data.webbridge_mixed_dataset.WebBridgeMixedDataset` handles view-padding to 14 and joint re-indexing at runtime, so a single model can be trained/evaluated on all five datasets.

## 3. Benchmark modes

| Mode | What it measures | Training data | Test data |
|---|---|---|---|
| **A. Zero-shot transfer** | Can an MPI-only model transfer to H36M/AIST/Shelf/Campus? | MPI only | All others |
| **B. Mixed-dataset training** | Does mixing all five datasets improve each one? | All datasets | Each dataset held out or its standard test split |
| **C. Leave-one-dataset-out** | Which dataset provides the most useful prior? | All except target | Target dataset |
| **D. Variable-view robustness** | Graceful degradation as views drop | Mixed | MPI/H36M with `k = 2..14` views |

Mode **B** is the primary ICRA/CVPR 2027 claim. Mode **A** exposes the cross-dataset gap; Mode **C** identifies negative/positive transfer; Mode **D** produces the variable-view curve needed for the paper.

---

## 4. AIST++ split

AIST++ has no official train/test partition in this repo. For the benchmark we adopt a style-based split:

* **Train:** all genres except `gBR` (break) and `gPO` (pop); i.e. `gWA`, `gKR`, `gJS`, `gHO`, `gMH`, `gLO`, `gJB`.
* **Test:** one sequence each from `gBR` (break) and `gWA` (walk) to cover fast/non-locomotion motion.

The actual list is generated by `experiments/prototypes/swarm_iter18/P18_cross_dataset_manifest.yaml` and can be regenerated with:

```bash
ls data/webbridge/aistpp_canonical/*.npz | sed 's/.*\///; s/_multiview.npz//' > tmp/aistpp_p18_test.txt
```

## 5. Models to benchmark

| Model | Role | Expected baseline |
|---|---|---|
| `crossview_residual_pp` (PP anchor) | Strong single-dataset baseline | ~9.32 mm MPI |
| `bayesian_tri_v2_pp` | Current best single-dataset ensemble member | ~8.35 mm MPI (28-joint) |
| `OmniMultiViewFusion` (P02) | Target unified 17-joint model | ≤ 8.0 mm MPI (17-joint) |

* For MPI-only mode the 28-joint model is evaluated on MPI-INF-3DHP with 28 joints.
* For cross-dataset modes, all models must output the common 17-joint skeleton, so MPI data is remapped before training/evaluation.

## 6. Evaluation harness

Use the existing harness:

```bash
python experiments/run_webbridge_benchmark.py \
    --manifest experiments/prototypes/swarm_iter18/P18_cross_dataset_manifest.yaml \
    --out outputs/P18_cross_dataset_plan/baseline
```

The harness reads `model_config` and the `datasets` list from the YAML, calls `experiments/eval_full_metrics.py` per dataset, and writes `summary.csv` + `summary.json`.

### 6.1 Metrics

Report per dataset and aggregate:

* **MPJPE** (mm) – primary.
* **PA-MPJPE** (mm).
* **PCK@50 / 100 / 150 mm**.
* **PCK-AUC**.
* **Per-joint MPJPE** for failure analysis.
* **Runtime** (clips/s) on CPU / RTX 4090 for reproducibility.

Aggregate reporting:

* **Macro average:** mean of per-dataset MPJPE.
* **Micro average:** pooled MPJPE over all frames across datasets.

## 8. Phased execution

### Phase 1 – Smoke & data audit (this PR)

* Run `P18_cross_dataset_smoke.py` to verify every `.npz` has the canonical keys and that MPI 28 → 17 re-indexing works.
* Confirm all dataset paths exist or document missing assets.

### Phase 2 – Zero-shot baselines

* Train/evaluate the MPI-only 17-joint `crossview_residual_pp` on H36M/AIST/Shelf/Campus.
* Establish the cross-dataset gap for the paper.

### Phase 3 – Mixed-dataset training

* Train `crossview_residual_pp` and `OmniMultiViewFusion` on the union of MPI (mapped to 17), H36M, AIST, Shelf, Campus.
* Report per-dataset and macro-average MPJPE.

### Phase 4 – Variable-view & analysis

* Generate MPJPE@k curves (`k = 2..14`) on MPI and H36M.
* Produce per-joint failure heatmaps and calibration-robustness matrices.

## 9. Success criteria

| Milestone | Target |
|---|---|
| MPI-INF-3DHP S2/Seq1 (17-joint) | ≤ 8.5 mm MPJPE |
| Macro-average MPJPE across 5 datasets | ≤ 12 mm |
| H36M S9/S11 (avg) | ≤ 5.5 mm MPJPE |
| AIST++ test | ≤ 7 mm MPJPE |
| Shelf / Campus | ≤ 10 mm MPJPE |
| Cross-dataset zero-shot H36M→MPI | < 30 mm MPJPE (large gap signals need for mixed training) |

---

## 10. Risks & mitigations

| Risk | Mitigation |
|---|---|
| MPI 28-joint → 17-joint mapping loses information | Verify reprojection error before/after mapping; keep 28-joint native MPI as a separate column |
| AIST++ has no official test split | Fix the style-based split in the manifest and document it exactly |
| Shelf/Campus pseudo-GT is noisy | Report both full and clean subsets; use as auxiliary transfer evidence |
| Mixed training destabilises the strong MPI baseline | Warm-start from PP anchor; freeze encoder for 3 epochs |
| Models trained with different joint counts cannot share a manifest | Maintain two manifests: `P18_native_joint_manifest.yaml` and `P17_17joint_manifest.yaml` |
