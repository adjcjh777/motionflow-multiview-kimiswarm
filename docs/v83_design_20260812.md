**Status:** Design proposal — do not implement without explicit go-ahead.

## 1. Background and motivation

| Run | Test MPJPE (mm) | S9 / S11 | PA-MPJPE | Notes |
|---|---:|---:|---:|---|
| v25 stability (A800) | **30.83** | 34.87 / 26.80 | 33.59 | Best learned true-GT result so far |
| v81 temporal-pose-attention | 37.83 | 42.19 / 33.46 | 37.75 | +7.0 mm over v25 stability |
| v82 multi-scale temporal-pose-attention | 39.46 | 42.07 / 36.84 | 39.94 | DONE; does not beat v25 stability; variable-view eval terminated before producing a curve |
| Iskakov ICCV 2019 | 23.35 | — | — | Strong geometric baseline |
| Conf-weighted DLT | 25.67 | — | — | Frozen reference |

**Observation:** v25 geometry fusion, when trained with a conservative recipe (low LR `1e-4`, 4-epoch warmup, no `variable_view_permute`), is the best-performing MotionFlow variant. Adding v81/v82 temporal self-attention **after** triangulation on the per-joint 3-D pose did **not** improve over the v25 stability recipe; v81 is **7.0 mm** worse and v82 is **8.6 mm** worse.

**Hypothesis:** Smoothing the final triangulated 3-D positions throws away per-view information and forces the model to average away view-specific noise. A better place for temporal reasoning is **before triangulation**, on the per-view ray/feature tokens, while conditioning on per-view reliability so that noisy or occluded views do not pollute the temporal context.

---

## 2. Proposed v83: View-Conditioned Temporal Attention

Add a lightweight **temporal attention module that operates on v25 ray tokens**, gated by per-view reliability. It is inserted inside `MultiViewGeometryFusionV25` between ray tokenization and the geometry-aware cross-view attention.

```
points_2d, K, R, t, confidence, view_mask
            │
            ▼
    ┌─────────────────────┐
    │  Initial DLT seed   │  ← v25 triangulate_initial
    └─────────────────────┘
            │
            ▼
    ┌─────────────────────┐
    │  RayTokenizer       │  ← (B, T, V, J, d)
    └─────────────────────┘
            │
            ▼
    ┌─────────────────────────────┐
    │  v83 View-Conditioned       │  ← NEW
    │  Temporal Attention         │
    │  (per-view temporal attn    │
    │   + cross-view reliability  │
    │   bias)                     │
    └─────────────────────────────┘
            │
            ▼
    ┌─────────────────────┐
    │  Geometry-aware     │  ← v25 cross-view attention
    │  cross-view attn    │
    └─────────────────────┘
            │
            ▼
    ┌─────────────────────┐
    │  Depth-proposal     │  ← v25 learned triangulation
    │  triangulation head │
    └─────────────────────┘
            │
            
      pred_3d_refined
```

### 2.1 What makes it different from v81/v82

- **Where the temporal reasoning happens:** v81/v82 attend over the final 3-D positions `(B, T, J, 3)`. v83 attends over **per-view ray tokens** `(B, T, V, J, d)` before triangulation.
- **View conditioning:** v81/v82 treat all views equally. v83 uses per-view reliability (from the v45 adaptive geometry fusion head or a small v80-style view-reliability head) as a soft attention bias, so unreliable/occluded views contribute less to the temporal context.
- **Identity-at-init:** like v81/v82, the new path is gated near zero at initialization, so training starts from the proven v25 stability baseline.

### 2.2 Module specification

**New file:** `motionflow_mv/fusion/view_conditioned_temporal_attention_v83.py`

**Class:** `ViewConditionedTemporalAttentionV83`

```python
class ViewConditionedTemporalAttentionV83(nn.Module):
    def __init__(
        self,
        d: int = 128,
        n_heads: int = 4,
        n_views: int = 4,
        temporal_window: int = 9,
        n_layers: int = 1,
        dropout: float = 0.1,
        residual_gate_init: float = -6.0,
        use_view_reliability_bias: bool = True,
    ):
        ...
```

**Forward signature:**

```python
def forward(
    self,
    tokens: torch.Tensor,          # (B, T, V, J, d)
    view_reliability: torch.Tensor, # (B, T, V) or (B, T, V, J)
    view_mask: Optional[torch.Tensor] = None,  # (B, T, V)
) -> torch.Tensor:               # (B, T, V, J, d)
```

**Internal mechanics:**

1. **Per-view temporal self-attention.** For each view `v` and joint `j`, run a masked temporal self-attention over the token sequence `tokens[:, :, v, j, :]`. Use the same local-window mask as v81 (`temporal_window`), extended to each view independently.
2. **Cross-view reliability bias.** After computing content-based attention scores, add a bias proportional to `log(view_reliability)` to the scores. Reliable views get stronger attention; low-reliability views are softly suppressed.
3. **Residual update.** Add the refined tokens to the original tokens via a learnable residual gate initialized to near-zero. Output projection is zero-initialized so the module is an identity no-op at start.

## 3. Integration points

### 3.1 Inside `MultiViewGeometryFusionV25`

Add a single optional call after `RayTokenizer` and before the geometry-attention loop:

```python
# tokens: (B, T, V, J, d)
tokens = self.ray_tokenizer(centre, direction, confidence)

# v83 optional temporal pre-refinement
if self.use_view_conditioned_temporal_attention_v83:
    view_reliability = self._compute_view_reliability(
        points_2d, pred_3d_init, K, R, t, view_mask
    )
    tokens = self.view_conditioned_temporal_attention_v83(
        tokens, view_reliability, view_mask=view_mask
    )

# existing v25 geometry-aware cross-view attention
...
```

The view-reliability can be provided by the existing `AdaptiveGeometryFusionV45` head (`motionflow_mv/fusion/adaptive_geometry_fusion_v45.py`) or the v80 `SparseViewReliabilityV80` head. If neither is enabled, reliability can default to uniform (`torch.ones(...)`).

### 3.2 New flags in `OmniMultiViewFusionV5`

## 4. Why this should close the gap

1. **Preserves the v25 baseline.** The new path is identity-at-init and gated, so it cannot make the v25 stability result worse at the start of training.
2. **Temporal smoothing is in the right place.** Per-view 2-D detections are noisy; smoothing the per-view evidence before triangulation is geometrically sound, whereas smoothing the final 3-D pose can only average errors.
3. **View conditioning prevents cross-view contamination.** Occluded or outlier views are common in the variable-view training used by v81/v82. v83 explicitly downweights them via reliability bias, which v81/v82 cannot do because they only see the fused 3-D pose.
4. **Low parameter count.** The module reuses the v25 `RayTokenizer` and adds only one or two temporal attention layers, so it fits the A800 disk/VRAM constraints and avoids the overfitting that plagued v80/v57.

---

## 5. Risks and mitigations

| Risk | Mitigation |
|------|------------|
| New path destabilizes v25 | Identity-at-init + gated residual; warm-start from v25 stability checkpoint |
| Reliability head not available | Fall back to uniform reliability (module reduces to plain per-view temporal attention) |
| Temporal window too small/large | Smoke sweep over `v83_temporal_window ∈ {5, 9, 13}` |
| Extra compute | Module is O(T·V·d²) per layer; clip_len is small (≤13) |
| Overfit on small H36M | Use v25 stability recipe (low LR, warmup, no permute) and EMA |

---

## 6. Success gates

A v83 candidate is worth keeping if it meets **both** gates on the true-GT H36M test:

1. **Primary gate:** test MPJPE < 30.83 mm (beats v25 stability).
2. **Robustness gate:** PA-MPJPE < 33.59 mm (beats v25 stability PA-MPJPE).

If the smoke run does not show at least a 1 mm val improvement over v25 stability by epoch 2, abandon the variant.
