# 3DPW Data Circularity Audit

## Scope

This audit evaluates whether the 3DPW (3D Poses in the Wild) data in this project can be used as **non-circular** ground truth for multi-view 3D human pose estimation.

3DPW is originally a **single-camera + IMU** in-the-wild dataset. The project converts it into two forms:

1. **Pseudo multi-view** (`converted/`, `converted_14views/`): a synthetic static camera rig is placed around the actor, and the 24 SMPL joints are re-projected into `V` virtual views.
2. **Actual single-view** (`validation/courtyard_basketball_01_actual.npz`): the real moving camera is preserved as a single view with per-frame intrinsics/extrinsics.

## Audit Methodology

We used the same circular-label diagnostic as the H36M / MPI / AIST++ audits:

```bash
python scripts/diagnose_circular_labels.py <path_to_npz>
```

The script re-triangulates the stored 2D keypoints (`points_2d`) with the stored cameras (`camera_K`, `camera_R`, `camera_t`) using unweighted DLT and compares the result to the stored 3D labels (`joints_3d`).

If the 3D labels are a deterministic function of the 2D inputs, the re-triangulated 3D will match the labels with **~0 mm error** → labels are **circular**.

The huge error for the actual-mode file is expected: with only one view, DLT triangulation is under-constrained and the stored camera is only a first-frame placeholder. The per-frame extrinsics are in `camera_K_frames`, `camera_R_frames`, and `camera_t_frames`, but a single-view setup still cannot produce a 3D label independent of the projection.

## Why pseudo 3DPW is circular

In `experiments/convert_3dpw_multiview.py`:

```python
def _build_pseudo_rig(...):
    # ...
    p2d = _project(joints_3d, actual_K, R, t)
```

The 2D keypoints are generated by **projecting the 3D labels** into the virtual camera views. By construction, triangulating those 2D points back-recovers the original 3D labels to numerical precision (0 mm). The 3D labels are not independent measurements of pose; they are the source of the 2D inputs.

## Verdict

- **Pseudo multi-view 3DPW (`converted/` and `converted_14views/`)**: ❌ **Cannot be used as non-circular ground truth.** The labels are perfectly recoverable from the 2D inputs via DLT triangulation. Training or evaluating on this data measures how well the model inverts the projection/triangulation pipeline, not true 3D pose accuracy.

- **Actual single-view 3DPW**: ⚠️ **Not usable as a multi-view dataset.** It is monocular and cannot provide independent 3D labels for triangulation-based evaluation. It may still be useful as an in-the-wild single-view domain sample, but that is outside the scope of this multi-view pipeline.

## Recommendations

1. **Do not train or benchmark on 3DPW pseudo multi-view** when the goal is to validate multi-view 3D pose estimation.
2. If in-the-wild domain transfer is needed, consider 3DPW **only** as a single-view domain adaptation source, not as ground truth for multi-view reconstruction.
3. For true in-the-wild multi-view evaluation, obtain a real synchronized multi-view dataset with independent 3D capture (e.g., marker-based mocap or multi-camera IMU fusion) rather than synthetic pseudo views.
