## 2. v84 Proposal A: Uncertainty-Weighted View Dropout (UWVD)

### 2.1 Idea

Instead of temporal smoothing, attack the next-obvious failure mode: **over-reliance on a fixed 4-view rig**. Add a lightweight per-view uncertainty head, then use that uncertainty both to **stochastically drop views during training** and to **reweight views during triangulation**. This forces the model to be robust to missing/weak views and produces calibrated triangulation weights.

### 2.2 Module sketch

**New file:** `motionflow_mv/fusion/uncertainty_weighted_view_dropout_v84.py`

```python
class UncertaintyWeightedViewDropoutV84(nn.Module):
    def __init__(
        self,
        d: int = 128,
        n_views: int = 4,
        n_joints: int = 17,
        hidden: int = 64,
        dropout_prob: float = 0.1,          # base view-dropout probability
        weight_type: str = "per_view",      # per_view | per_view_joint
        use_reprojection: bool = True,       # geometry cue for uncertainty
        use_epipolar: bool = True,           # second geometry cue
        min_weight: float = 0.05,
        identity_init: bool = True,
    ):
        ...
```

**Forward signature:**

```python
def forward(
    self,
    tokens: torch.Tensor,          # (B, T, V, J, d)
    points_2d: torch.Tensor,         # (B, T, V, J, 2)
    pred_3d: torch.Tensor,           # (B, T, J, 3)
    K, R, t,                         # camera parameters
    view_mask: torch.Tensor | None = None,
) -> tuple[torch.Tensor, torch.Tensor]:
    """Returns (refined_tokens, view_weights).

    refined_tokens: (B, T, V, J, d)
    view_weights:    (B, T, V) or (B, T, V, J)
    """
```

### 2.3 Internal mechanics

1. **Per-view uncertainty prediction.**
   - For each view, compute a small geometry residual: reprojection error of `pred_3d` to the view and a cross-view epipolar-style residual (deviation from mean reprojection error).
   - Concatenate the residual(s) with the pooled per-view token and pass through a 2-layer MLP.
   - Output is a log-variance `log σ²` per view (or per view-joint). Final layer is zero-initialised so the initial weight is uniform.

2. **Uncertainty-to-weight mapping.**
   - `weight_v = softmax(-log σ²_v)` over views.
   - Minimum weight clamped to `min_weight` to avoid zero triangulation.
   - Invalid views (per `view_mask`) are masked to zero before softmax.

3. **Training-time uncertainty-weighted view dropout.**
   - Sample a Bernoulli mask per view with `p_v = dropout_prob * (1 - normalized_uncertainty_v)`. More uncertain views are dropped more often.
   - The remaining views are re-normalized before triangulation.
   - This is applied inside the v25 training loop only; at inference all views are retained and weighted by uncertainty.
   - **Implementation note:** dropout must be applied before the learned depth-proposal triangulation head so the head sees the same view distribution it would see at inference (stochasticity is only in the dropout, not in the triangulation solver).

4. **Residual update.**
   - The uncertainty-weighted tokens are added back to the original ray tokens via a learnable residual gate (zero-initialized), so v25 behaviour is preserved at start of training.

### 2.4 Integration points

Inside `MultiViewGeometryFusionV25`, after the ray tokenizer and before triangulation:

```python
# tokens: (B, T, V, J, d)
if self.use_uwvd_v84:
    tokens, view_weights = self.uwvd_v84(
        tokens, points_2d, pred_3d_init, K, R, t, view_mask
    )
# existing v25 triangulation using view_weights
```

```python
v84_use_reprojection: bool = True,
v84_use_epipolar: bool = True,

```

### 2.5 Relation to existing reliability heads (v45 / v80)

The codebase already has two per-view reliability mechanisms:

- `AdaptiveGeometryFusionV45` (`motionflow_mv/fusion/adaptive_geometry_fusion_v45.py`): predicts per-view-joint weights from reprojection residuals and **re-triangulates** before ray tokenisation. It is deterministic and operates on 2-D residuals only.
- `SparseViewReliabilityV80` (`motionflow_mv/fusion/sparse_view_reliability_v80.py`): predicts per-view reliability from pooled tokens + residuals; used as a bias inside cross-view attention.

**v84 differs in three ways:**

1. **Dropout is data-dependent and stochastic.** v45/v80 are deterministic. v84 samples view subsets conditioned on estimated uncertainty, explicitly training the downstream triangulation head for sparse views.
2. **It operates on ray tokens, not just confidence.** The learned uncertainty is fed back into the token representation via a residual gate, not only into the DLT weights.
3. **It targets the triangulation step directly.** v84 weights are consumed by both the initial DLT seed and the learned depth-proposal triangulation head, giving a single coherent view-weighting signal.

## 3. v84 Proposal B: Hybrid Geometry + Appearance (HG+A)

### 3.1 Idea

The v25 ray tokens encode only geometric ray information. In real-world data, the 2D detector confidence already carries strong **appearance / visibility** information. Combine the geometry ray token with an appearance-like descriptor derived from the per-joint detection confidence and local image statistics, then use the combined representation in cross-view attention.

### 3.2 Why it might help

- v81/v82 temporal modules are geometry-only and cannot distinguish occluded views from clean ones.
- Adding a cheap appearance proxy (detection confidence + optional heatmap patch statistics) lets the model learn view-selection rules that go beyond reprojection error.
- It is a natural complement to Proposal A: uncertainty from geometry + appearance can be fused before dropout/reweighting.

### 3.3 Module sketch

**New file:** `motionflow_mv/fusion/hybrid_geometry_appearance_v84.py`

```python
class HybridGeometryAppearanceV84(nn.Module):
    def __init__(
        self,
        d_geo: int = 128,
        d_app: int = 32,
        n_views: int = 4,
        n_joints: int = 17,
    ):
        ...
```

**Appearance token (cheap version, no raw images required):**

- Input: per-joint 2D detection confidence `(B, T, V, J, 1)`, plus optional heatmap patch statistics (mean, std) if heatmaps are available.
- Project to `d_app` and concatenate to the geometry ray token.

**Hybrid attention:**

- Replace the v25 cross-view attention query/key with the concatenated geometry+appearance representation.
- Keep the value projection on the geometry component so the output still refines 3-D geometry.

### 3.4 Risk vs. Proposal A

| Risk | UWVD (A) | HG+A (B) |
|---|---|---|
| Needs new data | No — uses 2D points + cameras only | Maybe — heatmap patches not currently loaded |
| Parameter increase | ~10 k (small MLP) | ~50–100 k |
| Identity at init | Yes (zero-initialized gate) | Yes (appearance path zero-initialized) |
| Directly targets variable-view gap | Yes | Indirectly (better view selection) |

## 4. Recommended v84 path

**Primary recommendation: implement Proposal A (UWVD) first.**

- It reuses proven components (v25 geometry fusion + v80/v46-style reliability heads + uncertainty-weighted triangulation).
- It targets the known variable-view weakness without requiring temporal modules that have twice failed (v81/v82).
- It is identity-at-init and low-parameter, so the v25 stability baseline is preserved at the start of training.

**Proposal B (HG+A) should be kept as the next fallback** if UWVD also fails to beat v25 stability, or if heatmap/image patches become available.

---

## 5. Why this should close the gap

1. **Targets the real failure mode.** v81/v82 temporal attention tried to smooth away noise after triangulation. UWVD prevents noisy/occluded views from entering the triangulation in the first place.
2. **Variable-view robustness.** Variable-view evaluation shows catastrophic degradation at k=2/k=3. A learned uncertainty head should reduce the gap between k=4 and sparse subsets.
3. **Calibration.** Uncertainty weights give a principled way to combine views, moving closer to the strong DLT/Iskakov geometric baselines.
4. **Minimal intrusiveness.** Both proposals are gated residual additions; they can be toggled off, and the model falls back to v25.

---

## 6. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Uncertainty head destabilizes v25 | Zero-initialize output; warm-start from v25 stability checkpoint; use residual gate |
| View dropout is too aggressive | Sweep `v84_dropout_prob ∈ {0.0, 0.05, 0.1, 0.2}` on smoke |
| Uncertainty overfits to training cameras | Use view-independent residuals (reprojection + epipolar), not camera ID |
| HG+A needs heatmaps | Fallback to detection confidence only; skip if data loader not ready |
| Still does not beat v25 | Merge UWVD with v83 (view-conditioned temporal attention) for a v85 hybrid |
