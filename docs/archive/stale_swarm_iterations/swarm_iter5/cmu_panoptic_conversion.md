# CMU Panoptic → Canonical `.npz` Conversion

**Date:** 2026-08-04  
**Deliverable:** `experiments/convert_panoptic_v1.py`

## Summary

Implemented a self-contained downloader + converter that turns a CMU Panoptic
sequence into the canonical WebBridge multi-view `.npz` used by the
temporal ray-attention training pipeline.

The full HD videos are intentionally skipped; only the calibration JSON and the
`hdPose3d_stage1_coco19.tar` (3D body keypoints) are fetched.  From the 3D
keypoints, 2D detections are generated by projection through the calibrated HD
cameras, yielding a fully populated canonical `.npz` without multi-gigabyte
downloads.

## Sequence chosen

| Sequence | Calibration | 3D pose tarball | Frames | Cameras used |
|---|---|---|---|---|
| `171204_pose1_sample` | `calibration_171204_pose1_sample.json` (252 KB) | `hdPose3d_stage1_coco19.tar` (157 KB) | 101 | first 4 HD |

These two files are tiny, so the sample sequence is ideal for a reproducible
smoke-test pipeline.

## Usage

```bash
# Default: download and convert the sample sequence using 4 HD views
conda run -n mf python experiments/convert_panoptic_v1.py --n_views 4

# Download a different sequence, e.g. the full 171204_pose1
conda run -n mf python experiments/convert_panoptic_v1.py \
    --sequence 171204_pose1 \
    --n_views 4
```

## Canonical output format

```text
points_2d:   (T, V, J, 2)   projected 2D keypoints in pixels
confidences: (T, V, J)      per-joint confidence from Panoptic
joints_3d:   (T, J, 3)       3D ground-truth keypoints in meters
camera_K:    (V, 3, 3)       intrinsics
camera_R:    (V, 3, 3)       rotation (world-to-camera)
camera_t:    (V, 3)          translation (world-to-camera)
```

For the sample sequence with `--n_views 4`:

```text
points_2d:   (101, 4, 19, 2)
confidences: (101, 4, 19)
joints_3d:   (101, 19, 3)
camera_K:    (4, 3, 3)
camera_R:    (4, 3, 3)
camera_t:    (4, 3)
```

The skeleton is the COCO19 layout used by Panoptic (`joints19`).

## Verification

1. **Download succeeded.** Both the calibration JSON and pose tarball were
   fetched from `http://domedb.perception.cs.cmu.edu/webdata/dataset/171204_pose1_sample/`.
2. **Extraction succeeded.** The tar contains 101 `body3DScene_*.json` files.
3. **Projection sanity.** 2D points are in image space (≈ 80–1474 px), 3D joints
   are in meters (≈ −1.88 m to 0.77 m), and confidences are in [0.31, 0.74].
4. **Triangulation sanity.** Re-triangulating the projected 2D points with the
   saved camera matrices recovers the ground-truth 3D joints with a mean error
   of ≈ 4.3e-16 m (numerically zero), confirming the calibration and projection
   are self-consistent.
5. **Training loader compatibility.** `TemporalClipDataset` from
   `experiments/train_ray_attention_temporal_mpiinf3dhp.py` loads the `.npz`
   without modification and yields clips of shape `(13, 4, 19, 3)`.

## Important caveats

- **2D keypoints are synthetic projections.** Real detected 2D keypoints would
  require the HD videos + an off-the-shelf 2D pose estimator.  The current
  pipeline is sufficient for training multi-view fusion because the canonical
  format only requires calibrated 2D observations and 3D ground truth.
- **Units converted.** Panoptic stores 3D keypoints and camera translations in
  centimeters; the converter divides both by 100 to produce meters, matching the
  MPI-INF-3DHP canonical files.
- **Lens distortion is ignored.** The pinhole projection uses `K, R, t`; radial
  distortion coefficients are present in the calibration JSON but not applied.
- **Single-person sequences.** The script extracts `person_id=0` (default). For
  multi-person sequences, extend `--person_id` or merge per-person outputs.
- **No changes to existing files.** The new converter is kept in
  `experiments/convert_panoptic_v1.py`. The `convert_panoptic` stub in
  `motionflow_mv/data/webbridge_loader.py` remains untouched; integrating the
  new function into the WebBridge loader is left as a future cleanup step.

## No new dependencies

The script only uses `numpy`, `json`, `tarfile`, and `urllib.request`, all of
which are available in the existing `mf` environment.
