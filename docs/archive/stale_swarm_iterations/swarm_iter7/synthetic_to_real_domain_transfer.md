# Synthetic-to-Real Domain Transfer

**Topic:** synthetic-to-real transfer for the current best temporal residual model  
**Date:** 2026-08-04  
**Scope:** Extend the existing H36M-matched synthetic pipeline to `RayAttentionFusionModelTemporalResidual` and evaluate on MPI-INF-3DHP / Human3.6M.

---

## 1. Current state

The repo already has the pieces for synthetic-to-real transfer, but they target the **older non-temporal `RayAttentionFusionModelV3`** rather than the current best architecture.

Relevant files:

- `experiments/generate_synthetic_multiview_dataset.py:1-273` — SMPL-based synthetic generator tuned to the H36M camera distribution (focal ~ N(1147, 2.08) px, camera distance ~ N(5319, 523) mm, world scale 1000 for mm units). Supports `--camera_mode h36m|legacy`.
- `experiments/train_ray_attention_v3_transfer.py:1-228` — two-stage transfer trainer: pre-train on synthetic data, then fine-tune on real H36M.
- `motionflow_mv/fusion/ray_attention_temporal_model_domain.py:1-249` — a temporal model with a camera/domain MLP, but it is not wired into any synthetic-to-real trainer.
- `motionflow_mv/fusion/ray_attention_temporal_residual_model.py:1-227` — current best model (temporal ray-attention + per-joint residual MLP). It has **no synthetic pre-training script**.
- `experiments/train_ray_attention_temporal_residual_mpiinf3dhp.py:1-219` — current best trainer; trains only on real MPI-INF-3DHP clips.
- `docs/swarm_iter5/synthetic_to_real_transfer_h36m.md` — prior report showing the v3 transfer reached 4.75 mm val MPJPE on a tiny H36M subset.

## 2. Gap / opportunity

The current best model (`RayAttentionFusionModelTemporalResidual`) is trained from scratch on real data. A synthetic-to-real pipeline exists only for the older v3 model. Extending it to the temporal residual architecture could:

- Provide a strong pre-trained initialization before real-data training.
- Inject controlled domain randomization (camera rigs, noise, occlusion, outliers) that is hard to obtain from limited real datasets.
- Improve cross-subject / cross-dataset generalization, especially for MPI-INF-3DHP where real training data is small.

The synthetic generator outputs **non-temporal single frames**, so it can be reused, but a transfer trainer must assemble temporal clips from the synthetic frames.

## 3. Concrete next step

Add `experiments/train_ray_attention_temporal_residual_transfer.py` that:

1. Loads synthetic frames from `outputs/synthetic_multiview_dataset.npz` (generated by `generate_synthetic_multiview_dataset.py`).
2. Builds `TemporalClipDataset`/`RandomClipDataset` clips of length `clip_len=13` from synthetic frames, using the per-sequence camera rig.
3. Pre-trains `RayAttentionFusionModelTemporalResidual` on synthetic clips with the same augmentation as the real trainer (noise, dropout, outliers).
4. Loads the best synthetic checkpoint and fine-tunes on real MPI-INF-3DHP or H36M clips with a lower learning rate (e.g., 5e-4).
5. Saves the final checkpoint to `outputs/ray_attention_temporal_residual_transfer_mpiinf3dhp.pth`.

A minimal implementation can reuse:

- `TemporalClipDataset` / `RandomClipDataset` from `experiments/train_ray_attention_temporal_residual_mpiinf3dhp.py:40-99`.
- `augment_clip` from `experiments/train_ray_attention_temporal_residual_mpiinf3dhp.py:111-123`.
- The synthetic loader pattern from `experiments/train_ray_attention_v3_transfer.py:30-54`.

Quick smoke test command to add:

## 4. Expected success metric

- If transfer helps, the fine-tuned model should beat the current best **MPI-INF-3DHP MPJPE of 11.17 mm** on the S2/Seq1 validation set, or at least converge faster.
- On Human3.6M, expect the transferred model to match or improve the current **5.74 mm MPJPE** on S5.
- A useful intermediate signal: synthetic pre-training should reach low MPJPE on synthetic validation (< 5 mm) and the real fine-tune should start from a lower initial validation error than random initialization.

## 5. Risks / blockers

- **Synthetic/real domain gap:** The synthetic generator uses SMPL poses and H36M-matched cameras, but the motion distribution still differs from real subjects. Generating with more diverse SMPL poses (e.g., mocap sequences) may be needed.
- **Unit mismatch:** MPI-INF-3DHP data is in meters, while the synthetic generator defaults to mm (`world_scale=1000`). The trainer must scale consistently; the existing real trainer for MPI-INF-3DHP uses meter-scale data.
- **Temporal clips from synthetic frames:** The synthetic generator concatenates sequences, so the transfer trainer must not create clips across sequence boundaries.
- **A800-D / Docker read-only:** Training must run on the local RTX 4090. Do not modify A800-D containers or vendor data.
- **WebBridge data:** MPI-INF-3DHP real data is already in `data/webbridge/mpi_inf_3dhp/`, so no new downloads are required for the first experiment.
- **Large files:** Do not commit the synthetic `.npz` or large checkpoints to Git.
